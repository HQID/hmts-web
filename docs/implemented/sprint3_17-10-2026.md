## Implementasi

### Kas dan kuitansi

- `CreateCashTransactionAction`: otorisasi pengurus, validasi nominal positif maksimal 13 digit bulat/2 desimal, baca ulang akun di bawah `lockForUpdate()` dalam transaksi, penolakan akun nonaktif/saldo kurang. Saldo dihitung dengan integer sen, bukan aritmetika float; overflow `decimal(15,2)` ditolak.
- `VoidCashTransactionAction`: Gate superadmin, alasan 10–1000 karakter, baca ulang status transaksi dan kunci akun, pembalikan saldo serta audit pelaku/waktu atomik. Submit ulang dengan instance stale ditolak tanpa pembalikan ganda.
- Model `CashTransaction` menolak perubahan field ledger dan penghapusan melalui event Eloquent, dengan pengecualian transisi posted → voided beserta audit. Tidak ada endpoint edit/delete nominal.
- Perlindungan model **bukan immutability tingkat database**: raw SQL, bulk query builder, `saveQuietly()`, atau cascade database dapat melewati event. Batasi akses database dan review kode yang menulis ledger; jangan menganggap event ini pengganti prosedur void/Gate.
- Void pemasukan historis dapat menghasilkan saldo negatif jika dana sudah terpakai; ini mencerminkan koreksi ledger. Pengeluaran baru tetap membutuhkan saldo cukup. Saldo negatif dan pembalikan berikutnya diuji.
- `/app/kas`: form transaksi dengan pemulihan input/error, audit void, kontrol void khusus superadmin, ekspor, upload dan tautan kuitansi privat. Form pembuatan akun kas disediakan untuk instalasi baru, saldo awal selalu nol; pemasukan awal harus dicatat dalam ledger.
- Upload/download kuitansi memeriksa transaksi induk dengan scope periode. Download tetap memerlukan login, Gate pengurus dan temporary signed URL. Tidak ada link publik ke disk private.

### Proker dan panitia

- Form generik menggunakan nama field eksplisit untuk datetime/number; kategori/lokasi tidak lagi keliru menjadi datetime-local. Error kompilasi Blade yang ditemukan oleh tes halaman edit sudah diperbaiki.
- Edit judul/kategori/deskripsi/jadwal/lokasi/status proker melalui rute terbatas. Tanggal akhir dan status/kategori divalidasi; tidak membuat hard-delete arsip.
- Panitia wajib mengacu pada proker/anggota periode yang sama; status tugas dapat diperbarui melalui jalur yang sudah ada.
- `/kegiatan` menggunakan `Program` tersimpan dan scope periode, filter kategori dan modal rincian aktual. Data contoh, klaim kuota/hadiah, dan tautan TOR/registrasi fiktif dihapus. Upload TOR/registrasi tim tidak ditambahkan pada lingkup ini.

### Ekspor, periode, dan waktu

- CSV anggota/kas tetap native `streamDownload()`/`fputcsv()`, pemrosesan bertahap. Konten berawalan formula spreadsheet (termasuk whitespace sebelum `=`, `+`, `-`, `@`) diberi prefix apostrof; escaping koma, kutip dan newline diuji.
- GET `/login` kini mengarah ke beranda yang memiliki akses login, sehingga redirect tamu tidak berakhir pada HTTP method-not-allowed.
- `ActivePeriodScope` fail-closed: tanpa periode aktif/terpilih, data operasional kosong, bukan terbuka lintas arsip. Pemilihan periode yang memang sudah ada tetap dipertahankan.
- Timezone aplikasi menjadi `Asia/Makassar` sesuai label WITA. **Data waktu lama tidak dimigrasikan otomatis**; penafsiran UTC/WITA harus diperiksa sebelum deploy (lihat `docs/deployment.md`).

## Batas dan langkah berikutnya

1. Jalankan UAT di browser/perangkat nyata: login/logout, modal/fokus, tampilan mobile, QR kamera dan polling/countdown. Tes HTTP/Livewire tidak membuktikan perilaku kamera atau JavaScript browser.
2. Jalankan konkurensi kas/peminjaman di database **MySQL staging terpisah**; SQLite tidak menguji row lock MySQL. Jangan arahkan RefreshDatabase ke database pengguna.
3. Audit interpretasi timestamp lama sebelum perubahan UTC → WITA dipakai pada data nyata. Jangan menggeser data delapan jam tanpa rekonsiliasi.
4. Ikuti `docs/deployment.md`: backup/restore, PHP sesuai lockfile (**>=8.4.1 melalui Symfony 8**, walau composer.json mencantumkan ^8.3), private storage, HTTPS, debug off, provisioning superadmin/periode, smoke test, dan rollback aman.
5. Deployment belum dilakukan dan tidak dianggap lulus hanya karena build lokal berhasil. Klaim penutupan Sprint 2 juga diperjelas dalam laporan terkait agar tidak menyiratkan seluruh alur browser/produksi sudah diuji.
